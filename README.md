# Unit 1 Academy — BTEC Level 3 IT, Unit 1 (IT Systems)

An interactive learning platform: real 3D hardware, a PC builder, a rule-based 3D & 2D networking lab, a Gemini-powered study assistant grounded in the textbook, quizzes, games, and an assignment coach. English by default, full Arabic (RTL) support, dark/light themes.

## 🚀 طريقة التشغيل (Quick Start)

```bash
npm install
cp .env.example .env        # أضف مفتاح GEMINI_API_KEY (اختياري للمساعد الذكي)
npm run dev                 # تشغيل بيئة التطوير: الواجهة على :5173 والخادم على :8787
```

صفحة الواقع المعزّز متاحة على `/ar`. عرض النماذج ثلاثي الأبعاد يعمل على الحاسوب، أما وضع النموذج في الغرفة فيتطلب هاتفاً ومتصفحاً يدعمان WebXR واتصالاً آمناً عبر HTTPS أو localhost.

لتشغيل نسخة الإنتاج أو الاختبارات:

```bash
npm run build && npm start  # بناء المشروع وتشغيله على المنفذ :8787
npm test                    # تشغيل جميع الاختبارات الآلية
```

## 🎬 قصة مختبر الـ BTEC (Story mode) — `/story`

قصة تفاعلية ثلاثية الأبعاد تبدأ بطلب الأستاذ ياسر في مكتب المدير أبو أنيس وتنتهي بمختبر جاهز:
الحوار ← الموافقة ← تكليف الأستاذ علاء ← الصف الفاضي ← ترتيب 25 طاولة ← تجميع جهاز المعلم (Tiny) ← تنصيب البرامج ← توزيع أجهزة الطلاب ← كبينة الشبكة ← التمديدات ← الطابعة والـ UPS والشاشة ← الفحص النهائي ← التسليم.

| الملف | الوظيفة |
|---|---|
| `src/story/config/labLayout.js` | توزيع الصف (عدد الطاولات على كل حيطة، مكان الباب، الكبينة، المكيف، الـ UPS…) — **عدّل الأرقام هنا فقط** |
| `src/story/config/dialogues.js` | نصوص الحوارات والخيارات (عربي/إنجليزي) — كل المسارات تلتقي عند نفس النقطة |
| `src/story/config/assets.js` | ربط الصور المرجعية بالشخصيات والمعدات (`public/story/refs/`) |
| `src/story/config/software.js` | خطوات تنصيب البرامج (أسماء قابلة للتعديل) |
| `src/story/config/network.js` | محتوى الكبينة وخطة ربط المنافذ |
| `src/story/tinyAssembly.js` | قواعد تجميع جهاز Tiny (كرت شاشة مدمج، محوّل طاقة خارجي) وفحص POST |
| `src/story/dialogue.js` · `storyState.js` | محرك الحوار، حالة القصة، الحفظ التلقائي، والفحص النهائي |
| `src/three/story/*` | المشهد ثلاثي الأبعاد: الصف، المكتب، الشخصيات المتحركة، الكاميرا السينمائية، نموذج جهاز Tiny |
| `src/pages/Story.jsx` · `src/story/ui/*` | واجهة اللعبة (الحوار، اللوحات، الإيقاف المؤقت، الفصول) |

ملاحظات: الشخصيات نماذج مبسّطة متحركة مبنية على ملامح الصور (ليست مسحاً ثلاثي الأبعاد للوجوه). داخل الكبينة توزيع تعليمي لأن الصورة لا تُظهره. نظام امتحان التوجيهي عنصر توضيحي فقط. كل الفحوصات محاكاة.

اختبارات القصة: `tests/story.test.js` (ضمن `npm test`).

## 📎 استوديو الواجب المدعوم بالذكاء الاصطناعي (Assignment Studio)

يرفع الطالب ملف واجبه (PDF / DOCX / TXT حتى 8MB) من صفحة `/assignment`، فيُستخرج النص على الخادم ثم يُحلَّل عبر Gemini لتوليد مساحة عمل شخصية (ملخص السيناريو، المهام والمعايير، دروس، قائمة تخطيط، تمارين، كلمات الأوامر) مع **خطوة أولى** بدل إجابة جاهزة.

| الملف | الدور |
|---|---|
| `server/lib/extract.js` | استخراج النص (PDF نصي، DOCX، TXT) مع التحقق من نوع الملف من محتواه، ورفض الملفات الممسوحة/الفارغة/التالفة |
| `server/lib/assignment/` | خط التحليل: `identify` ← `connect` ← `prepare`، التحقق من مخرجات الذكاء الاصطناعي، حماية من حقن التعليمات |
| `server/lib/gemini.js` | الاتصال الوحيد بـ Gemini (يُستخدم أيضاً من `/api/chat`) |
| `server/data/reference/` | واجبات Pearson المرجعية؛ بعد إضافة ملفات شغّل `npm run kb:refs` لفهرستها في `reference-chunks.json` |
| `src/pages/Assignment.jsx`, `src/components/assignment/` | الواجهة (رفع، مراحل التحليل، مساحة العمل) |
| `shared/assignment-context.js` | سياق الواجب النشط الذي يراه المساعد الذكي |

**الإعداد:** `GEMINI_API_KEY` على الخادم فقط. بدونه يعمل «التحليل الأساسي» (بدون ذكاء اصطناعي) ويعرض فقط ما وُجد فعلاً في المستند.
**ملاحظات:** لا يوجد OCR (الملفات الممسوحة تُرفض برسالة واضحة). تُحفظ النتائج في `localStorage` للمتصفح نفسه (لا حسابات طلاب)، ويُحفظ الملف المرفوع في ذاكرة الخادم لمدة ساعة فقط. الاختبارات: `npm test`.

## النشر على Render وربطه بـ GitHub

يوجد ملف `render.yaml` لإعداد خدمة الويب تلقائياً. الخدمة تبني الواجهة وتشغّل خادم API معاً، وتستخدم مسار `/api/health` لفحص جاهزيتها.

1. ارفع ملفات المشروع إلى مستودع GitHub.
2. في Render اختر **New + → Blueprint**، ثم اربط حساب GitHub واختر هذا المستودع والفرع المطلوب.
3. عند إعداد الخدمة، أدخل قيمة `GEMINI_API_KEY` عندما يطلبها Render. ويمكنك إضافتها أو تغييرها لاحقاً من **Dashboard → الخدمة → Environment → Add Environment Variable**.
4. احفظ المتغيرات، وانتظر اكتمال النشر. سيعطيك Render رابطاً عاماً للموقع. فعّل **Auto-Deploy** من إعدادات الخدمة إذا لم يكن مفعّلاً، كي يُنشر كل تحديث تدفعه إلى الفرع المرتبط.

ضع قيمة مفتاح Gemini في Render كمتغير `GEMINI_API_KEY` فقط؛ لا تضع المفتاح في ملفات المشروع أو GitHub، ولا تستخدم بادئة `VITE_`. ملف `.env.example` يحتوي على مثال توضيحي وليس مفتاحاً حقيقياً. بعد إضافة المفتاح، أعد النشر؛ ويمكنك التأكد من أن الذكاء الاصطناعي مفعّل عبر `https://رابط-خدمتك/api/health` (الحقل `ai` يجب أن يكون `true`).

صفحة القصة والأصوات تعمل على الاستضافة الثابتة. ميزات المساعد الذكي ورفع الواجب تحتاج خادم API، لذلك لا تعمل على GitHub Pages وحده.
